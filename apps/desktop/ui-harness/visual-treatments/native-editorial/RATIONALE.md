# Native editorial

This treatment gives the finished meeting note the most deliberate typography in
the window. It uses an installed serif reading stack for the title and note
body, while all chrome stays in the system interface face. The contrast makes
the document feel authored and readable without turning the utility into a web
article.

## Neutrals and depth

The palette is a low-chroma graphite family in dark appearance and a soft
stone family in light appearance. Pane separation comes from small neutral
steps, one-pixel rules, and the document's quieter elevation; it does not use
tint as a substitute for hierarchy. Red remains recording-only, amber carries
attention, and blue only marks source evidence.

## Controls and selection

The toolbar is deliberately short. Search and the disabled Record explanation
remain readable but truncate rather than becoming a second toolbar sentence.
Rename and Manage are quiet text-like secondary controls. The selected meeting
gets a low-contrast neutral fill and a narrow inset edge, so it is easy to find
but cannot outrank the document title.

## Sparse-state composition

The sparse note begins with a type-led header and a compact factual annotation,
then uses distinct editorial blocks for overview, personal notes, and the
transcript. The notes field has a bounded, surfaced writing area with a useful
minimum height; this makes it clearly editable without consuming the lower
window as an unmarked void.

## Appearance and accessibility

Both appearances preserve the same tonal steps and hierarchy. Secondary copy
is intentionally brighter than a decorative caption so metadata, disabled
state, and notes help remain legible at normal Mac distance. Keyboard focus is
a clear blue outline, hover changes are optional and short, and no meaning
depends on color alone. The attention state uses a label, copy, and button rank
in addition to amber.

## Known risks

The serif note system can feel slightly more reflective than operational during
live capture; a capture-specific frame should be judged before product adoption.
The long disabled Record explanation is necessarily truncated at this window
width, which preserves toolbar geometry but requires an accessible full string
on the element that owns it.
